Qué es

El backend es la parte de una aplicación que se ejecuta en el servidor: recibe las peticiones de la web, de la app móvil o de otros sistemas, aplica las reglas del negocio, lee y guarda datos y responde. El usuario no lo ve, pero es donde vive casi toda la lógica.

Esta área trata el backend en Java y en su marco más usado, Spring. Tiene cuatro partes:

  • Backend en Java: los cimientos, como HTTP, la API de Servlets (la forma estándar de atender peticiones web en Java), la inyección de dependencias y la configuración.
  • Spring Framework: el marco y su familia de proyectos (Boot, MVC, Data, Security, Cloud…).
  • ORM y persistencia: guardar objetos Java en bases de datos relacionales con JPA, Hibernate, JDBC y transacciones.
  • Construcción y dependencias: compilar, empaquetar y gestionar librerías con Maven o Gradle.

El lenguaje Java en sí está en el área de Fundamentos de ingeniería de software; aquí se trata lo necesario para construir servidores con él.

Siglas

  • HTTP (Hypertext Transfer Protocol): el protocolo de petición y respuesta de la web y de casi todas las API.
  • API (Application Programming Interface): la interfaz con la que otros programas usan tu backend; en la web suele ser una API REST sobre HTTP.
  • ORM (Object-Relational Mapping): el puente entre los objetos del programa y las tablas de una base de datos.
  • JPA (Jakarta Persistence API): el estándar de ORM en Java; Hibernate es su implementación más usada.
  • JDBC (Java Database Connectivity): la API básica de Java para lanzar SQL a una base de datos; todo lo demás se apoya en ella.

Por qué importa

Java con Spring es una de las combinaciones más usadas para el backend de empresa: banca, seguros, telecomunicaciones, comercio y administración pública tienen sistemas críticos escritos así, muchos de ellos con años de vida por delante. Por eso hay una demanda estable de perfiles que lo dominen. Y es la base sobre la que se montan el resto de piezas del mapa: API, mensajería, pruebas, despliegue o integración de IA.

Por dónde empezar

  1. Java, si aún no lo dominas.
  2. HTTP, la API de Servlets y la inyección de dependencias: lo que Spring automatiza.
  3. Maven, para crear y construir proyectos.
  4. Spring Framework, empezando por Spring Core y Spring Boot.
  5. JPA, Hibernate y las transacciones, junto con Spring Data.

Caso real: Kopi Chess

Kopi Chess (código público) es un backend en Java 25 y Spring Boot 4 hecho para leerse: arquitectura hexagonal con un módulo Maven por anillo y reglas de ArchUnit, un dominio de ajedrez en Java puro verificado con perft, casos de uso sin Spring, PostgreSQL con SQL escrito a mano y migraciones Flyway, una cola de trabajos con FOR UPDATE SKIP LOCKED, hilos virtuales, métricas con decoradores y pruebas con Testcontainers. El caso completo, con el código explicado: Aprendizajes de Kopi Chess.
