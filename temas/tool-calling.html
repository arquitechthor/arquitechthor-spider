Qué es

El Tool Calling (o function calling) es el mecanismo por el que un modelo de lenguaje puede pedir que se ejecute una función de tu aplicación: consultar una base de datos, buscar en un catálogo, llamar a otra API. El modelo no ejecuta nada: devuelve el nombre de la herramienta y los argumentos en JSON; tu código la ejecuta y le devuelve el resultado para que siga.

Es la pieza que convierte un chat en un agente: un modelo que, además de hablar, puede consultar datos reales y actuar.

Vocabulario para empezar

  • Definición de herramienta: lo que el modelo ve de cada función: un nombre, una descripción en lenguaje natural y un esquema JSON de sus parámetros.
  • Turno: cada ida y vuelta con la API. Una pregunta del usuario puede necesitar varios turnos si el modelo pide herramientas en cadena.
  • Orquestador: el código que gestiona ese ir y venir (en Java, normalmente LangChain4j o Spring AI). Ver orquestación.

Por qué importa

Un LLM solo sabe lo que aprendió al entrenarse y lo que le pones en el contexto. Con herramientas puede trabajar con datos actuales y propios (el stock de hoy, las reglas que ya existen, el árbol de categorías de un cliente) sin meterlos todos en el prompt. Además permite repartir el trabajo: lo que necesita lenguaje lo hace el modelo; lo que es determinista (buscar un id, comprobar una regla, calcular un precio) lo hace Java, que no se equivoca ni cuesta tokens.

Cómo funciona: el bucle

  1. La aplicación envía el mensaje del usuario junto con la lista de herramientas disponibles.
  2. El modelo responde con texto o con una o varias peticiones de herramienta (nombre y argumentos).
  3. La aplicación valida los argumentos, ejecuta cada herramienta y añade los resultados a la conversación.
  4. Vuelve a llamar al modelo con todo lo anterior. Se repite hasta que el modelo da la respuesta final o se llega a un límite de pasos.

Este bucle es la base del bucle de agente. Los proveedores permiten además forzar el comportamiento con una opción de elección de herramienta: que decida el modelo, que use alguna obligatoriamente o que use una concreta.

Conceptos clave

  • La descripción es el contrato: el modelo elige herramienta por su nombre y su descripción. Explica cuándo usarla, cuándo no, y qué devuelve. Las instrucciones del prompt de sistema («usa siempre X antes de proponer una regla») refuerzan cuándo llamarla.
  • Argumentos no fiables: los argumentos los inventa el modelo. Valídalos como cualquier entrada de usuario y no aceptes del modelo datos que ya conoces por otra vía (el usuario autenticado, el cliente de la ruta).
  • Resultados compactos: lo que devuelve la herramienta entra en el contexto y se paga en tokens. Devuelve solo lo necesario: los cinco nodos que coinciden, no el árbol entero.
  • Errores como resultado: si la herramienta falla, devuelve un mensaje que el modelo entienda («no existe la categoría 123») en lugar de lanzar una excepción que corte el bucle.
  • Subagentes como herramienta: una herramienta puede ser otro agente especializado (por ejemplo, uno que solo traduce frases a códigos). El agente principal delega y recibe una respuesta acotada.
  • Herramientas en paralelo: muchos modelos pueden pedir varias herramientas en el mismo turno; el orquestador puede ejecutarlas a la vez.
  • MCP: un protocolo estándar para publicar herramientas en un servidor y que cualquier aplicación o asistente las use. Ver MCP.

En la práctica

En LangChain4j, una herramienta es un método Java anotado. El orquestador genera la definición a partir de la firma y las descripciones:

class CatalogoTools {

    private final Catalogo catalogo;

    CatalogoTools(Catalogo catalogo) { this.catalogo = catalogo; }

    @Tool("Busca categorías por id o por nombre. Devuelve como mucho 5 coincidencias con su ruta completa.")
    List<CategoriaResumen> buscarCategoria(@P("Id numérico o texto a buscar") String consulta) {
        return catalogo.buscar(consulta, 5);
    }
}

interface Asistente {
    String chat(@UserMessage String mensaje);
}

Asistente asistente = AiServices.builder(Asistente.class)
        .chatModel(modelo)
        .tools(new CatalogoTools(catalogo))
        .build();

Cuando el usuario escribe «manda los bolsos a la 3020», el modelo puede pedir buscarCategoria("3020"), recibir la ruta real de esa categoría y proponer la regla con un dato comprobado, en vez de dar por buena una categoría que quizá no existe.

Errores frecuentes

  • Demasiadas herramientas: con decenas de herramientas parecidas, el modelo se confunde. Agrupa, renombra o reparte entre subagentes.
  • Pasar datos enormes al modelo: mandar un catálogo de miles de nodos en cada llamada es caro, lento y empeora la precisión. Busca en Java y devuelve solo lo relevante.
  • Herramientas con efectos sin confirmación: borrar, pagar o guardar algo importante debería pasar por una confirmación humana (ver humano en el bucle).
  • Bucles sin límite: fija un número máximo de pasos para que un error no encadene llamadas sin fin.
  • Confiar en que siempre la llamará: el modelo puede decidir no usarla. Si una comprobación es obligatoria, hazla también en código después.
  • Inyección de prompts por los resultados: un texto devuelto por una herramienta (una web, un correo) puede contener instrucciones maliciosas. Ver inyección de prompts.
