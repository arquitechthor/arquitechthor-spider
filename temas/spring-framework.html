Qué es

Spring Framework es un marco de código abierto para Java, nacido a principios de los 2000 como alternativa más sencilla al Java empresarial de la época. Su núcleo es un contenedor: tú escribes clases normales y el contenedor las crea, las configura y las conecta entre sí. A ese principio se le llama inversión de control (IoC), y la forma de aplicarlo, inyección de dependencias (DI): cada objeto recibe ya hechas las piezas que necesita en lugar de crearlas él. Los objetos que gestiona el contenedor se llaman beans.

Sobre ese núcleo se apoya todo lo demás: la web, el acceso a datos, las transacciones, la seguridad… Cuando se habla de «Spring» se suele hablar de toda esa familia de proyectos, no solo del marco: Spring Boot (2014) lo hace práctico con configuración automática y servidor incluido, y proyectos como Spring Data, Spring Security, Spring Cloud o Spring AI cubren cada necesidad. Las versiones actuales son Spring Framework 7 y Spring Boot 4, de finales de 2025.

Siglas

  • IoC (Inversion of Control): el marco crea y conecta tus objetos, en vez de hacerlo tu código.
  • DI (Dependency Injection): la forma concreta de IoC en Spring; las dependencias llegan por el constructor (lo recomendado) o por métodos.
  • AOP (Aspect-Oriented Programming): añadir lógica común alrededor de métodos sin tocarlos. Así funcionan en Spring @Transactional o la seguridad por métodos.
  • MVC (Model-View-Controller): el patrón que da nombre a Spring MVC, el módulo web clásico.

Por qué importa

Es el marco más extendido en el backend Java: bancos, aseguradoras, administraciones y empresas de todos los tamaños lo usan, y aparece en la mayoría de ofertas de empleo de Java. Saber cómo funciona por dentro (el contenedor, los beans, la configuración automática, los proxies que aplican transacciones y seguridad) es lo que separa usarlo de entenderlo, y lo que más se pregunta en entrevistas. También tiene certificación propia, que este sitio cubrirá más adelante.

Cómo encajan las piezas

  • Base: Spring Core (el contenedor y los beans) y Spring Context (el contexto de la aplicación: perfiles, propiedades, eventos).
  • Arranque: Spring Boot, que configura casi todo solo a partir de las dependencias.
  • Web: Spring MVC (un hilo por petición, el modelo clásico) y Spring WebFlux (reactivo, para muchas conexiones con pocos hilos).
  • Datos y seguridad: Spring Data (repositorios sin escribir consultas a mano) y Spring Security (autenticación y permisos).
  • Sistemas grandes: Spring Cloud (microservicios: configuración centralizada, descubrimiento de servicios) y Spring Batch (procesos por lotes).
  • IA: Spring AI, que vive en el área de IA y aparece aquí como acceso.

Por dónde empezar

  1. Antes, Java y la idea de inyección de dependencias.
  2. Spring Core y Spring Context: qué es un bean, cómo se crea y cómo se conecta.
  3. Spring Boot y Spring MVC: tu primera API.
  4. Spring Data (con JPA) y Spring Security.
  5. Después, según el proyecto: Spring Cloud, Spring Batch, Spring WebFlux o Spring AI.
