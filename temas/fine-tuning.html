Qué es

El fine-tuning (ajuste fino) consiste en tomar un modelo ya entrenado y seguir entrenándolo con un conjunto de datos propio, más pequeño y especializado. Cambia los parámetros del modelo (los números que aprendió), así que el resultado es un modelo nuevo, adaptado a tu tarea, que ya no necesita que se lo expliques todo en cada prompt.

Es un caso de aprendizaje por transferencia (transfer learning): se aprovecha lo que el modelo ya sabe del lenguaje en general y solo se le enseña lo específico. Por eso basta con cientos o miles de ejemplos, en vez de los billones de tokens del entrenamiento original.

Vocabulario para empezar

  • Modelo fundacional (foundation model, en inglés se abrevia FM): un modelo grande entrenado con enormes cantidades de datos generales que sirve de base para muchas tareas distintas. Los LLM son el ejemplo más conocido.
  • Preentrenamiento (pre-training): el primer entrenamiento, el que crea el modelo fundacional desde cero. Cuesta millones y solo lo hacen unos pocos laboratorios.
  • Datos etiquetados: ejemplos que incluyen la respuesta correcta (una pregunta con la respuesta que se espera). Sin etiquetar: texto suelto, sin respuesta asociada.
  • Pesos: otro nombre de los parámetros del modelo.

Formas de adaptar un modelo entrenando

  • Ajuste por instrucciones (instruction tuning): fine-tuning con pares de instrucción y respuesta deseada («resume este informe» → el resumen bueno). Es lo que convierte un modelo que solo completa texto en uno que sigue órdenes, y la forma habitual de enseñarle una tarea, un formato o un tono.
  • Adaptación a un dominio: especializar el modelo en un campo (medicina, derecho, el vocabulario de un sector) para que entienda su jerga y sus convenciones.
  • Preentrenamiento continuo (continued pre-training): seguir entrenando con grandes cantidades de texto sin etiquetar de un dominio (todos los manuales técnicos de una industria, por ejemplo). Aporta conocimiento y vocabulario de fondo; no enseña una tarea concreta.
  • RLHF: personas comparan varias respuestas del modelo y eligen la mejor; con esas preferencias se ajusta el modelo para que responda más como prefieren. Es una de las técnicas con las que los laboratorios hacen que sus modelos sean útiles y seguros.
  • Destilación (distillation): un modelo grande (el «profesor») genera respuestas y con ellas se entrena uno pequeño (el «alumno») para que lo imite en una tarea concreta. El alumno es más barato y rápido de usar y, en esa tarea, se acerca mucho al profesor.

Hay además una variante técnica que conviene conocer: PEFT. En vez de modificar todos los pesos, se congela el modelo y se entrenan unas pocas piezas añadidas. La más conocida es LoRA, que entrena matrices pequeñas junto a las originales: cuesta una fracción y el resultado ocupa muy poco.

Cuándo compensa (y cuándo no)

La regla práctica es ir de lo barato a lo caro y no subir un escalón hasta que el anterior se quede corto:

El aprendizaje dentro del contexto (in-context learning), dar ejemplos en el prompt, no entrena nada: el coste está en los tokens que añades a cada petición. El fine-tuning invierte al revés: paga una vez por entrenar (y por alojar el modelo propio) y luego los prompts son más cortos.

Para lo que no sirve bien: meterle datos que cambian. Lo aprendido queda fijo en los pesos hasta el siguiente entrenamiento, no se puede citar de dónde sale y no se puede restringir por usuario. Para eso, RAG. Los dos se combinan: un modelo ajustado para el estilo y RAG para los datos.

Preparar los datos

La calidad del modelo ajustado depende sobre todo de los datos, más que de la técnica:

  • Curados: revisados a mano, sin errores ni respuestas que no quieras que imite. El modelo aprende también lo malo.
  • Representativos: que cubran los casos reales, incluidos los difíciles y los poco frecuentes, y variados para que no aprenda un solo patrón.
  • Bien etiquetados: con la respuesta que de verdad quieres, escrita de forma coherente.
  • Del tamaño justo: para un ajuste por instrucciones se empieza con cientos o pocos miles de ejemplos buenos; mil ejemplos excelentes valen más que cien mil mediocres.
  • Con gobierno: saber de dónde sale cada dato, con qué permiso se usa, y quitar datos personales o confidenciales que no deban acabar dentro del modelo.

Y antes de entrenar, separa un conjunto de prueba que el modelo no vea, para medir si el ajuste mejora de verdad respecto al modelo base con un buen prompt.

Riesgos

  • Olvido catastrófico: al especializarse, el modelo puede empeorar en cosas que antes hacía bien. Hay que probar también tareas generales.
  • Sobreajuste (overfitting): con pocos datos o demasiado entrenamiento, memoriza los ejemplos en vez de aprender el patrón, y falla con casos nuevos.
  • Coste de mantenimiento: cuando sale una versión mejor del modelo base, el ajuste hay que repetirlo.
  • Fugas: lo que entra en el entrenamiento puede salir en una respuesta. Nada de secretos ni datos personales en el conjunto.

Así se hace en AWS

Amazon Bedrock permite personalizar algunos de sus modelos con fine-tuning, preentrenamiento continuo y destilación sin gestionar servidores: se suben los datos a S3 y Bedrock entrena una copia privada del modelo. Para un control total del entrenamiento está Amazon SageMaker AI, y SageMaker JumpStart ofrece modelos abiertos listos para ajustar.

Caso real: por qué Prompt Quest no usa fine-tuning

En Prompt Quest, el juego de agentes del autor de esta web, un LLM traduce la estrategia de cada jugador a reglas en JSON. Podría pensarse en ajustar un modelo con miles de ejemplos de estrategia y reglas, pero no hizo falta. Las reglas del juego (clases, elementos, objetos y acciones) van en el prompt de sistema, generadas desde el propio código del motor; el formato se garantiza con un JSON Schema; y el código valida el resultado. Así, cuando cambia el equilibrio del juego (más vida para una clase, un objeto nuevo), el prompt se actualiza solo y no hay que reentrenar nada: el escalón de prompt bien diseñado era suficiente.

Errores frecuentes

  • Empezar por el fine-tuning: casi siempre un buen prompt, con ejemplos y RAG si hacen falta datos, resuelve el problema antes y más barato.
  • Usarlo para que el modelo «se sepa» los documentos: para conocimiento que cambia o que hay que citar, RAG.
  • Pocos datos o de mala calidad: el modelo aprende los errores y las rarezas del conjunto.
  • No medir contra el modelo base: sin un conjunto de prueba aparte no sabes si el ajuste ha mejorado algo.
  • Confundir preentrenamiento continuo con fine-tuning: el primero usa texto sin etiquetar para aprender un dominio; el segundo, ejemplos etiquetados para una tarea.
