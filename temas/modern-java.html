Qué es

«Java moderno» es el nombre informal del lenguaje tal y como ha quedado tras más de diez años de cambios, desde Java 8 (2014) hasta Java 25 (2025). En ese tiempo Java ha ganado funciones anónimas (lambdas), clases que solo guardan datos (record), jerarquías cerradas (sealed), un switch que descompone objetos, hilos casi gratis y programas de un solo fichero sin clase.

No es una versión ni un producto: es una forma de escribir Java. El mismo programa escrito al estilo de Java 6 y al estilo de Java 25 puede ocupar la mitad y, sobre todo, dejar al compilador comprobar cosas que antes solo se veían al ejecutar.

Por qué importa

  • Es el Java que vas a encontrar. Spring Boot 3 exige Java 17 como mínimo, y las librerías actuales ya usan record, sealed y switch con patrones en sus API.
  • El compilador trabaja por ti. Con un tipo sellado y un switch exhaustivo, olvidar un caso es un error de compilación, no un fallo en producción.
  • Menos código que mantener. Un record sustituye a decenas de líneas de constructor, getters, equals, hashCode y toString.
  • Rendimiento sin tocar el código. Los hilos virtuales o la caché AOT mejoran aplicaciones existentes casi sin cambios.

Vocabulario para empezar

  • JDK: el kit de desarrollo de Java: compilador (javac), máquina virtual (JVM) y librerías. «Instalar Java 25» es instalar un JDK 25.
  • JEP: la propuesta con la que se diseña cada cambio de Java. Tiene número (los record son la JEP 395) y su página explica qué cambia y por qué. Es la fuente de verdad de cada novedad.
  • Calendario: desde Java 10 (2018) sale una versión cada seis meses, en marzo y septiembre. Así, Java 26 salió en marzo de 2026 y Java 27 en septiembre de 2026.
  • LTS: las versiones con soporte de varios años, una cada dos años: 8, 11, 17, 21 y 25 (la siguiente será la 29). Las empresas suelen saltar de LTS a LTS; las versiones intermedias reciben parches solo seis meses.
  • Preview (vista previa): una novedad completa pero aún no definitiva. Solo funciona compilando y ejecutando con --enable-preview, y puede cambiar o desaparecer en la versión siguiente. Cuando se da por buena, pasa a final y ya no cambia.

Las versiones que marcan época

  • Java 8 (2014, LTS): lambdas, streams, Optional, la API de fechas java.time y métodos por defecto en las interfaces. El gran salto hacia la programación funcional.
  • Java 11 (2018, LTS): var (llegó en la 10), el cliente HTTP estándar y ejecutar un fichero .java sin compilarlo antes. Fue el primer LTS del calendario de seis meses.
  • Java 17 (2021, LTS): switch como expresión, bloques de texto, record y clases selladas, todo ya definitivo. El mínimo de Spring Boot 3.
  • Java 21 (2023, LTS): hilos virtuales, switch con patrones, patrones de registro y colecciones secuenciadas.
  • Java 25 (2025, LTS): variables sin nombre _ (desde la 22), comentarios en Markdown (23), Stream Gatherers (24), cuerpos de constructor flexibles, ficheros fuente compactos y la caché AOT.
  • Java 26 y 27 (2026): sobre todo mejoras de la JVM y de seguridad (HTTP/3 en el cliente HTTP, intercambio de claves poscuántico en TLS). Las novedades del lenguaje que siguen llegando, como la concurrencia estructurada o las constantes perezosas, seguían en preview en Java 26.

Lambdas y streams (Java 8)

Una lambda es una función sin nombre que se pasa como valor; un stream es una tubería de operaciones sobre una colección (filtrar, transformar, agrupar) que se describe en lugar de programarla con bucles. Tienen ficha propia: Streams & Lambda Expressions.

List<String> nombres = usuarios.stream()
        .filter(u -> u.activo())          // una lambda: recibe u, devuelve un boolean
        .map(Usuario::nombre)              // referencia a método
        .sorted()
        .toList();                         // Java 16: lista inmutable, sin Collectors

var: inferencia de tipos locales (Java 10)

var deja que el compilador deduzca el tipo de una variable local a partir de lo que se le asigna. El tipo sigue siendo fijo y se comprueba al compilar: Java no se vuelve dinámico.

var porNivel = new EnumMap<Nivel, List<Pregunta>>(Nivel.class); // el tipo ya se lee a la derecha
var total = calcular();   // peor: ¿qué devuelve calcular()? El lector no lo ve

Úsalo cuando el tipo es evidente en la propia línea; evítalo cuando obliga a ir a otro sitio para saber qué es. Solo vale para variables locales, no para atributos ni parámetros.

switch como expresión y bloques de texto (Java 14 y 15)

El switch con flecha (->) devuelve un valor, no «se cuela» al caso siguiente (adiós a los break olvidados) y admite varias etiquetas por caso. Los bloques de texto (""") escriben cadenas de varias líneas sin concatenar ni escapar comillas.

int dias = switch (mes) {
    case FEBRERO -> bisiesto ? 29 : 28;
    case ABRIL, JUNIO, SEPTIEMBRE, NOVIEMBRE -> 30;
    default -> 31;
};

String sql = """
        SELECT id, nombre
        FROM usuario
        WHERE activo = true
        """;

Records (Java 16)

Un record es una clase cuyo único propósito es llevar datos. Con declarar sus componentes, el compilador genera el constructor, un método de acceso por componente (nombre(), sin get), equals, hashCode y toString. Sus campos son final: un record no se modifica, se crea otro.

public record Casilla(int columna, int fila) {
    public Casilla {                       // constructor compacto: solo validar
        if (columna < 0 || columna > 7 || fila < 0 || fila > 7) {
            throw new IllegalArgumentException("Fuera del tablero");
        }
    }
}

var e4 = new Casilla(4, 3);
e4.equals(new Casilla(4, 3));   // true: dos records son iguales si sus datos lo son

Encajan como objetos de valor, DTO, mensajes, eventos o claves de un mapa. No sustituyen a las entidades de JPA, que necesitan ser modificables y tener un constructor sin argumentos.

Pattern matching: instanceof, switch y patrones de registro (Java 16–22)

Un patrón comprueba la forma de un objeto y, si encaja, extrae sus partes en variables, todo en un paso. Llegó por etapas:

  • instanceof con patrón (16): if (o instanceof String s) comprueba y declara s sin el cast de después.
  • switch con patrones (21): cada case puede ser un tipo, con una condición extra opcional (when).
  • Patrones de registro (21): case Punto(var x, var y) descompone un record en sus componentes, y se pueden anidar.
  • Variables y patrones sin nombre (22): _ marca lo que no se va a usar: case Circulo _, catch (IOException _).
static double area(Figura f) {
    return switch (f) {
        case Circulo(var radio)            -> Math.PI * radio * radio;
        case Rectangulo(var a, var b) when a == b -> a * a;   // un cuadrado
        case Rectangulo(var a, var b)      -> a * b;
    };
}

El orden importa: los casos se prueban de arriba abajo, y el compilador rechaza un caso que nunca se puede alcanzar porque otro anterior ya lo cubre.

Clases e interfaces selladas (Java 17)

Una interfaz o clase sealed enumera quién puede implementarla o heredar de ella. Nadie más puede. Así el compilador conoce todos los casos posibles, y un switch sobre ella que los cubra todos no necesita default: es exhaustivo. Si mañana se añade un caso, cada switch que no lo trate deja de compilar.

public sealed interface Figura permits Circulo, Rectangulo {}
public record Circulo(double radio) implements Figura {}
public record Rectangulo(double ancho, double alto) implements Figura {}

Cada subtipo debe declararse final, sealed o non-sealed (este último vuelve a abrir la jerarquía por esa rama); los record ya son final. Si los subtipos están en el mismo fichero, permits se puede omitir.

Records + sealed + switch forman juntos lo que otros lenguajes llaman tipos algebraicos: modelar «un resultado es esto, o esto, o esto» con datos y dejar que el compilador vigile que se tratan todos los casos. Es la novedad que más cambia cómo se diseña el código, y choca a propósito con el principio abierto/cerrado de SOLID: conviene cuando el conjunto de casos es fijo (las reglas de un juego, los estados de un pedido) y no cuando terceros deben poder añadir los suyos.

Colecciones secuenciadas (Java 21)

Tres interfaces nuevas, SequencedCollection, SequencedSet y SequencedMap, dan a toda colección con orden los mismos métodos: getFirst(), getLast(), addFirst(), removeLast() y reversed(). Antes, obtener el último elemento era lista.get(lista.size() - 1) en una List y algo distinto en cada otra colección.

Hilos virtuales (Java 21)

Un hilo virtual es un hilo que gestiona la JVM, no el sistema operativo: crearlo cuesta casi nada y, cuando se bloquea esperando (una consulta, una respuesta HTTP), libera el hilo real para que otro trabaje. Permiten escribir código bloqueante sencillo, un hilo por petición, y aun así atender miles de peticiones a la vez. Desde Java 24 un bloque synchronized ya no deja «clavado» el hilo real. Se ven a fondo en Concurrency & Multithreading.

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    pedidos.forEach(p -> executor.submit(() -> procesar(p)));  // un hilo virtual por pedido
}

Stream Gatherers (Java 24)

Los streams tenían operaciones fijas (map, filter…). gather() admite operaciones intermedias a medida, y la clase Gatherers trae algunas hechas, como ventanas de elementos consecutivos:

Stream.of(1, 2, 3, 4).gather(Gatherers.windowSliding(2)).toList();  // [[1, 2], [2, 3], [3, 4]]
Stream.of(1, 2, 3, 4).gather(Gatherers.windowFixed(2)).toList();    // [[1, 2], [3, 4]]

Comentarios de documentación en Markdown (Java 23)

La documentación del código (Javadoc) se puede escribir con /// en Markdown en lugar de HTML dentro de /** … */: **negrita**, listas con guiones, `código` y enlaces a otras clases con [Clase]. Se lee igual de bien en el fichero que en la documentación generada.

Cuerpos de constructor flexibles (Java 25)

Hasta Java 24, la llamada a super(...) o this(...) tenía que ser la primera línea del constructor. Ahora se pueden poner antes sentencias que validen argumentos, preparen valores e incluso asignen campos de la propia clase, siempre que no usen el objeto que se está construyendo (this).

public PrecioPositivo(BigDecimal valor) {
    if (valor.signum() <= 0) {
        throw new IllegalArgumentException("El precio debe ser positivo");  // antes de super(...)
    }
    super(valor);
}

Ficheros fuente compactos y main de instancia (Java 25)

Un programa pequeño ya no necesita clase ni public static void main(String[] args). El fichero declara directamente sus métodos, y el compilador los envuelve en una clase implícita. La nueva clase IO (java.lang.IO) da println y readln sin importar nada:

// Hola.java: se ejecuta con «java Hola.java», sin compilar antes
void main() {
    var nombre = IO.readln("¿Cómo te llamas? ");
    IO.println("Hola, " + nombre);
}

Sirve para aprender, para guiones y para utilidades de desarrollo. Desde Java 22, java Hola.java también compila y ejecuta programas de varios ficheros.

La caché AOT: arrancar antes (Java 24 y 25)

Al arrancar, la JVM lee, verifica y enlaza miles de clases y empieza a observar qué métodos se usan más para optimizarlos. La caché AOT hace ese trabajo una vez, en una ejecución de entrenamiento, y lo guarda en un fichero que leen los arranques siguientes. Java 24 trajo la carga y el enlace anticipados de clases (JEP 483); Java 25 lo simplificó a una sola opción (JEP 514) y añadió los perfiles de los métodos (JEP 515).

java -XX:AOTCacheOutput=app.aot -jar app.jar   # entrenamiento: crea la caché
java -XX:AOTCache=app.aot -jar app.jar         # arranques normales: la usan

La caché solo vale para la misma JVM y los mismos jar; si no encaja, la JVM arranca igual, sin ella. El código de la aplicación no cambia.

Lo que está en preview

En Java 25 había en vista previa, entre otras, la concurrencia estructurada (tratar varias tareas en paralelo como una sola: si una falla, se cancelan las demás), los valores estables (constantes que se calculan la primera vez que se usan; en Java 26 pasaron a llamarse lazy constants) y los patrones con tipos primitivos. En Java 26 las tres seguían en preview, y las constantes perezosas, también en Java 27. Probarlas está bien; construir una aplicación sobre ellas obliga a revisarla en cada versión.

Caso real: Kopi Chess

Kopi Chess (código público, Java 25 y Spring Boot) es un programa de ajedrez escrito, entre otras cosas, para practicar Java moderno: cada cambio explica en sus notas qué novedad usa y por qué. Estos son los ejemplos más claros.

Una jugada es uno de seis tipos, y el compilador lo sabe

Qué hace una jugada además de mover una pieza (capturar, enrocar, comer al paso, coronar…) es una interfaz sellada con seis record. Los que no tienen datos están vacíos; el enroque guarda el lado y la coronación, la pieza nueva:

public sealed interface MoveKind {
    record Quiet() implements MoveKind {}
    record Capture() implements MoveKind {}
    record DoublePawnPush() implements MoveKind {}
    record EnPassant() implements MoveKind {}
    record Castling(CastleSide side) implements MoveKind { … }
    record Promotion(PieceType piece, boolean capture) implements MoveKind { … }

    default boolean isCapture() {
        return switch (this) {
            case Capture _, EnPassant _ -> true;
            case Promotion(_, var capture) -> capture;
            case Quiet _, DoublePawnPush _, Castling _ -> false;
        };
    }
}

En un solo método aparecen los tipos sellados, el switch exhaustivo sin default, un patrón de registro que extrae capture y _ para lo que no interesa. Aplicar la jugada al tablero (Position.apply) es otro switch sobre los seis tipos: un séptimo no compilaría hasta tratarlo allí (MoveKind.java, Position.java).

Una evaluación con condición en el patrón

La valoración de Stockfish es una ventaja en centésimas de peón, un mate en N jugadas o un jaque mate ya dado. Para saber si un bando tiene mate, el when afina un caso:

default OptionalInt mateFor(Color side) {
    return switch (this) {
        case Centipawns _ -> OptionalInt.empty();
        case MateIn(var moves) when (moves > 0) == (side == Color.WHITE) -> OptionalInt.of(Math.abs(moves));
        case MateIn _ -> OptionalInt.empty();
        case Checkmate(var winner) -> winner == side ? OptionalInt.of(0) : OptionalInt.empty();
    };
}

(Evaluation.java)

Validar antes de super(...)

Una posición de ajedrez se escribe como texto en notación FEN. Si el texto está mal, la excepción construye su mensaje y guarda sus campos antes de llamar al constructor del padre, algo que antes de Java 25 no compilaba:

InvalidFenException(Problem problem, String fen, String detail) {
    Objects.requireNonNull(problem, "problem");
    var message = problem + " in FEN \"" + fen + "\": " + detail;
    this.problem = problem;
    this.fen = fen;
    super(message);
}

(InvalidFenException.java)

Ventanas de dos posiciones con un Gatherer

Para calcular la precisión de cada jugada hay que comparar la posición de antes con la de después. windowSliding(2) convierte la lista de posiciones en pares consecutivos sin índices a mano:

// Cada jugada es el paso de una posición a la siguiente.
var steps = positions.stream().gather(Gatherers.windowSliding(2)).toList();

(AnalysisSummary.java)

La caché AOT, medida

La imagen Docker hace el entrenamiento al construirse: arranca la aplicación con -XX:AOTCacheOutput, deja que Spring cree su contexto y sale (sin base de datos: las migraciones y los procesos de análisis se apagan para el entrenamiento). Los arranques reales añaden -XX:AOTCache. Medido en un portátil, Spring pasó de arrancar en 4,8–5,8 s a hacerlo en 2,5–3,2 s, casi la mitad, sin tocar una línea de Java (Dockerfile, notas de la medición).

Las preview, en cuarentena

La aplicación solo usa novedades definitivas. Las que están en vista previa se practican en un módulo aparte, kopi-labs, el único compilado con --enable-preview, y una prueba de arquitectura rompe la compilación si otro módulo lo usa. Su primer ejemplo analiza varias posiciones en paralelo con concurrencia estructurada: si un análisis falla, los demás se cancelan (ADR-012, PositionBatchAnalyser.java).

Errores frecuentes

  • Poner default en un switch sobre un tipo sellado: compila, pero anula la ventaja. Si se añade un caso, el default lo traga en silencio en lugar de avisar.
  • Creer que un record es inmutable del todo: sus campos no se reasignan, pero si uno es una List modificable, la lista sí cambia. Cópiala en el constructor compacto (List.copyOf).
  • Usar record como entidad JPA: JPA necesita objetos modificables con constructor vacío. Los record van bien para proyecciones y DTO.
  • var en todas partes: si el lector tiene que adivinar el tipo, se ha perdido claridad. Es una herramienta de legibilidad, no un atajo de tecleo.
  • Agrupar hilos virtuales en un pool (un conjunto fijo de hilos que se reutilizan): no hace falta y estorba; se crea uno por tarea. Para limitar el acceso a un recurso escaso, como las conexiones a la base de datos, se usa un semáforo (Semaphore, un contador de permisos: quien no consigue uno, espera).
  • Usar preview en producción: obliga a ejecutar siempre con --enable-preview y puede romperse al actualizar el JDK. Mejor aislarlas, como hace Kopi Chess.
  • Quedarse en Java 8 «porque funciona»: se pierde soporte de librerías (Spring Boot 3 ya no arranca en Java 8 ni en 11) y las mejoras gratuitas de rendimiento de la JVM.

Por dónde empezar

  1. Pasa a la última LTS que admitan tus dependencias (hoy, Java 25; si no, Java 21).
  2. Empieza por lo que no cambia el diseño: var con criterio, bloques de texto, switch con flecha, toList() y getFirst()/getLast().
  3. Convierte en record los objetos que solo llevan datos (DTO, eventos, resultados).
  4. Cuando un valor sea «uno de estos casos y ningún otro», modélalo con sealed y trátalo con switch y patrones, sin default.
  5. En servicios con mucha espera (base de datos, HTTP), prueba los hilos virtuales; con Spring Boot basta con spring.threads.virtual.enabled=true.
